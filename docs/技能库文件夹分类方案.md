# 技能库文件夹分类方案

调研日期：2026-11-14。下文现状表为分类前的调研快照，实际实施结果见本节。

## 本轮实施结果

- 本轮完成一次实际整理及分类浏览、分类安装的代码适配；文中设计的通用批量移动/分类重命名界面仍是后续功能，未作为现有能力提供。

验证结果：`vue-tsc --noEmit`、前端构建通过；补充归档分类后 Rust 库测试 130 项通过、2 项联网测试按默认规则跳过；Windows WebView2 隔离集成脚本通过，包括分类回收站的界面还原、旧条目兼容、分类联合筛选、视图一致性和勾选清理检查。测试不在真实技能库中执行写入。

## 结论

采用“实体文件夹作为主分类、现有标签作为辅助分类”。支持 `技能库根目录/外层/分类/子分类/技能/SKILL.md` 等多层结构，保留根目录直接存放技能的兼容性。

实现顺序：统一分类浏览 → 补齐安装与路径兼容 → 提供可预览、可恢复的分类迁移 → 整理现有技能库。分类功能属于显式的库管理操作；扫描、部署仍不得修改技能内容。

## 1. 已核实的现状

| 项目 | 当前行为 | 对方案的影响 |
| --- | --- | --- |
| 本机技能库 | 应用配置为 `E:\my-skills`；当前扫描规则可识别 68 个技能，全部在根目录 | 可以先拟定分类清单，再统一迁移 |
| 扫描深度 | `scan.rs` 的 `visit_skills` 已支持根目录技能，以及“分类/技能”两层结构 | 复用现有扫描器，无须新增递归扫描器 |
| 技能边界 | 目录存在 `SKILL.md` 时即作为一个完整技能，不再深入其内部 | `nuwa-skill/examples` 中的 15 个示例不应被当成独立安装的技能 |
| 列表视图 | `SkillAllocation.vue` 只有关键词过滤，没有分类入口 | 默认列表需要接入分类筛选 |
| 卡片视图 | `Skills.vue` 已有分类按钮，但只有“全部+至少两个分类”时才显示 | 当前全部平铺，分类栏不显示；收藏入口也被这个条件一起隐藏 |
| 按 Agent 视图 | `AgentConfig.vue` 已按 `category` 分组 | 继续复用分类字段并统一筛选行为 |
| 根目录文案 | `(根)` 在卡片分类按钮中被显示为“全部技能” | 应改为“未分类”，与跨目录的“全部技能”区分 |
| 技能标识 | `key` 是相对路径，如 `code` 或 `开发工程/code` | 分类移动会改变标识，必须迁移相关配置 |
| Agent 部署 | 链接名称取技能目录最后一段，目标为技能的实际路径 | 分类后 Agent 端仍可保持平铺，但链接目标必须更新 |
| 市场安装 | GitHub 市场的部分已安装判断及安装落点仍使用 `root/name` | 必须先修复，否则分类后可能误判未安装并重复下载 |

另外，本机已经存在 Agent 目录链接和收藏/标签数据；第三方 `.skills_store_lock.json` 中有 9 条安装记录，其 `installDir` 当前均不存在。这只能证明记录与磁盘不一致，不能据此认定技能已删除，也不应自动改写第三方记录。

`E:\my-skills` 本身是 Git 仓库，当前有未提交的修改、删除及未跟踪文件。分类迁移必须保留这些已有状态，不自动提交、推送或清理。

## 2. 推荐目录结构

```text
E:\my-skills\
├─ 01-开发工程\
│  ├─ dev-expert\SKILL.md
│  └─ frontend-design\SKILL.md
├─ 02-写作运营\
│  └─ wechat-article\SKILL.md
├─ 03-视觉设计\
│  └─ wechat-cover\SKILL.md
├─ 04-音视频与交互\
├─ 05-文档知识库\
├─ 06-搜索研究\
├─ 07-Agent与技能管理\
├─ 08-自动化与日常\
├─ 新下载的技能\SKILL.md       ← 界面归入“未分类”
├─ _archive\                  ← 延续现有排除规则
├─ .git\                      ← 延续现有排除规则
└─ 其他现有文件                ← 不参与技能分类
```

分类目录使用中文便于浏览，数字前缀提供稳定顺序；技能自身的文件夹名称及内部文件保持原样。

一个技能只放一个主分类。跨用途通过标签表达，例如 `baoyu-xhs-images` 放在“视觉设计”，增加“小红书、运营”标签，避免复制多份产生更新分歧。现有标签目前用于标注，分类方案应同时补上标签筛选。

现有整理使用一层分类，v1.2.0 起也可以按需增加包装目录和子分类。技能内部的 `scripts`、`references`、`examples` 均随整个技能目录保留，遇到技能目录后不再将其内部示例独立扫描。

## 4. 界面交互

技能库页面增加固定的分类侧栏，右侧保留现有列表和卡片视图：

```text
技能分类                  技能库                 [列表] [卡片] [按 Agent]
全部技能           68     [搜索名称、描述、路径…] [标签筛选] [仅收藏]
未分类              0
开发工程           10     当前分类：开发工程 · 10 个技能
写作运营            8     □ dev-expert           [现有 Agent 分配开关]
视觉设计           11     □ frontend-design      [现有 Agent 分配开关]
音视频与交互        9     ...
文档知识库          6
搜索研究            6     [全选当前结果] [移动到分类…] [预览分配]
Agent与技能管理    12
自动化与日常        6
```

- 分类筛选由页面统一持有；列表、卡片复用同一个过滤结果，避免两个视图各自计算而不一致。
- “按 Agent”保留现有分类分组，并接入相同的分类选择；搜索框按当前视图职责展示。
- “全部技能”“未分类”“仅收藏”始终可用，不受实际分类数量影响。
- 分类、关键词、标签和收藏条件取交集；分类计数展示库内总数，结果区另外显示当前匹配数。
- 切换分类或关键词后清空批量勾选，避免隐藏选中项造成操作歧义。全选只作用于当前结果。
- 单项和批量均通过“移动到分类”操作，支持直接输入新分类名。初版不做拖拽、AI 自动分类或复杂树形管理。
- 记住上次选择；目录刷新后若分类已消失，回到“全部技能”。

## 5. 分类迁移必须处理的关联数据

例如 `code` → `01-开发工程/code`，不只是改一个 `category` 字段。

| 关联项 | 必须处理的行为 |
| --- | --- |
| 技能目录 | 整体移动，保持技能内部相对路径与文件内容不变 |
| `agent_configs[*].enabled_skills` | 将旧 key 精确替换为新 key，不影响其他待部署配置 |
| `skill_meta` | 将收藏与标签迁移到新 key；目标已有记录时应报告冲突 |
| 实际 Agent 链接 | 在移动前记录实际指向旧技能的受管链接，移动后仅更新这些链接的目标，保留链接名称 |
| 同名外部技能 | 保留，不按目录名猜测归属，不覆盖实体目录或外部链接 |
| 共享 Agent 目录 | 按真实路径去重，同一个链接只处理一次 |
| 链接转换恢复记录 | 核查 `skill_link_backups` 中的 key、原目录及目标路径，确保恢复校验仍有明确语义 |
| 历史部署回滚 | 原记录可能引用旧目标；不可直接沿用旧路径恢复。首版可明确阻止跨分类迁移边界的旧部署回滚，并提供独立的迁移恢复入口，避免改写历史审计 |
| 导出清单与旧清单导入 | 新导出使用新 key；旧清单导入时依据迁移映射预览转换，找不到唯一映射则提示，不按同名自动匹配 |
| 安装与更新 | 已安装判断使用技能索引；更新复用当前实际位置，新装支持选择分类，默认根目录“未分类” |
| Git 同步与备份 | 验证分类路径保持完整，防止与迁移并发；不自动提交或推送 |
| 第三方安装记录 | 检测并提示路径不一致；未验证第三方格式与更新行为前不自动改写，也不承诺外部 CLI 更新兼容 |

现有即时分配会保护目标不一致的链接，因此不能简单采用“先移动文件夹、然后全部重新启用”的办法。需要专门的迁移操作，保存并验证旧目标后再定向更新链接。

首版保留现有相对路径 key，使用迁移映射处理改名和恢复；暂不引入全库 UUID、数据库或多级目录系统，降低对同步、清单和部署格式的影响。

## 6. 迁移执行流程

1. **只读预览**：产生旧路径、新路径、旧/新 key、受影响配置及实际链接清单，同时记录状态指纹。
2. **校验**：分类名必须是合法的单层目录名，不允许路径分隔符、隐藏/保留前缀、Windows 保留名或库外路径；检查大小写冲突、目标占用与链接边界。
3. **冲突报告**：分类目录不能本身包含 `SKILL.md`；不同分类下同名技能在 Agent 端仍会争用同一个链接名，需要明确阻止同一 Agent 同时分配冲突项，不自动覆盖。
4. **确认具体变更**：展示移动数量、涉及 Agent 和每项冲突。第三方管理状态不能确认的条目默认跳过，保留原位。
5. **持久化恢复记录**：在修改前保存配置快照、旧/新映射、链接目标及操作阶段；已有用户修改与 Git 状态原样保留。
6. **执行**：串行处理这次迁移，重 I/O 放在 `spawn_blocking`；禁止与安装、删除、部署或同步交叉写入。配置锁只覆盖短临界区。
7. **提交配置并校验**：以预览指纹检查外部修改，持久化新配置，再重扫并验证受管链接指向有效技能。不能将扫描失败误报为迁移成功。
8. **故障恢复**：出现错误按记录逆序恢复；恢复失败保留记录并明确列出未恢复项。下次启动检测未完成迁移，提供恢复入口，不能把多步文件操作称为天然原子操作。

新产生的分类迁移映射与恢复记录由应用管理，不写入技能正文，不把本机绝对路径或凭证提交进技能 Git 仓库。

| 批次 | 内容 | 完成标准 |
| --- | --- | --- |
| 第一批：分类浏览 | 页面共享分类筛选、侧栏、未分类文案、收藏与标签入口；复用 `category` | 人工构造的两层技能库，在列表、卡片、按 Agent 中看到一致结果 |

分类重命名、合并、拖拽排序、自动推荐分类可在后续出现明确需求时再做。分类重命名必须复用同一迁移流程，不能绕过 key 和链接更新。

## 8. 验证重点

使用 `commands::test_scratch(tag)` 创建隔离夹具，不用真实技能库或 Agent 配置执行变更测试。

- 根目录技能、两层分类、混合结构均能扫描；识别技能后停止向内部递归，隐藏和归档目录保持排除。
- 单项、批量、重复请求、中文分类、大小写冲突、非法路径及分类目录本身含 `SKILL.md`。
- 收藏标签、期望配置和实际链接同时存在差异时，分类移动只处理明确受影响项。
- 外部实体目录、库外链接、共享目录和同名技能保持边界。
- 在目录移动、链接更新、配置写入各阶段注入失败，验证逆序恢复与重启恢复；存在外部修改时停止覆盖。
- 分类后的市场已安装识别、安装目标、更新、清单导入、备份恢复以及旧部署回滚限制。
- 前端运行 `vue-tsc` 与构建；后端运行相关回归测试和库测试，再做桌面手工验证。
