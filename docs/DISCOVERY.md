# 本机发现与内置技能

界面现已统一为黑白 / 蓝白风格，设计参考与主题约定见 [DESIGN.md](DESIGN.md)。

## 发现策略

程序在启动、点击「重新扫描」以及应用重新获得焦点（距上次扫描超过 30 秒）时扫描，耗时操作在线程池执行。范围限定为已知产品目录、PATH、Windows 安装登记、运行进程、开始菜单快捷方式、常见安装位置与 IDE 扩展安装清单，不递归扫描整块磁盘，也不执行发现的 Agent 程序。

| 界面状态 | 判定依据 | 含义 |
| --- | --- | --- |
| 已确认安装 | PATH 中的命令、有效安装登记、运行进程、开始菜单指向的实际程序，或安装清单与包信息一致的 IDE 扩展 | 找到了程序侧的证据 |
| 检测到配置 | 已知产品的配置或技能目录、显式环境变量 | 有使用痕迹，不能据此保证程序仍然安装 |
| 待确认 | 通用 `~/.xxx/skills` 扫描命中的未知目录 | 用户确认后接入，不自动猜测产品 |
| 路径不可用 | 已保存的 Agent 没有有效路径证据 | 保留原配置，供用户检查 |
| 共享目录 | `.agents/skills` 等跨工具约定 | 不作为一个已安装的 Agent 计数 |

所有发现功能合并到「设置 → Agent 工具 / 内置技能」，侧栏不再提供独立发现入口。

默认只展示已安装工具；没有程序侧证据的产品规则与残留配置放入「未安装 / 待确认」，不能参与技能分配。内部产品目录知识库用于匹配路径，不直接等同于本机安装列表。

每个已安装工具提供持久化的「允许配置」开关，新发现的工具默认关闭；旧版本已登记的工具在确认仍已安装后保留原有管理状态。关闭后从总览、Agent 配置、技能分配与上下文统计中隐藏，原链接和原分配记录保留。后端在部署、回滚、分配、导入链接和收编外部技能等入口统一检查开关与安装证据；扫描失败或尚未完成时禁止配置。清单导入也不会覆盖关闭工具的分配；删除仍由关闭工具使用的共享技能会被拒绝，防止间接改变它。

「重新扫描」只读取本机信息，不自动登记或重新开启工具。技能目录尚未存在但安装已确认时显示「部署时创建」。工具安装或卸载后可重新扫描刷新列表；配置前会再次检查程序或扩展证据文件是否仍存在。

「自定义工具」支持名称、唯一 ID、绝对技能路径、可选程序路径，以及 MCP 配置文件和格式。未知工具需提供现存技能目录或实际程序文件；已确认的 IDE 扩展也可以编辑后续使用的技能目录。自定义信息与开关本地保存，已有路径优先于知识库默认值。

Windows 查询仅获取产品名称、安装位置、图标位置和进程可执行路径，不读取进程命令行、凭据或会话内容；系统查询有 12 秒超时，失败后继续提供目录与 PATH 的结果并展示提示。豆包输入法、更新器不会被当作 Agent；Claude Desktop 不会被当作 Claude Code。

## 可移植路径

- 用户根目录来自 `USERPROFILE`，其他平台回退 `HOME`。
- 应用数据根目录来自 `LOCALAPPDATA`、`APPDATA`。
- 支持 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`GEMINI_CLI_HOME`、`OPENCLAW_STATE_DIR` 和适用产品的 `XDG_CONFIG_HOME`。
- 新技能库默认在当前用户目录的 `AgentSkillHub/skills` 下；已有技能库位置保持原样。
- 对旧版本保存的内置默认路径进行迁移，不依赖作者的用户名。自定义目录不被猜测改写。
- 豆包优先使用实际存在的旧内部用户技能目录，否则使用当前用户的 `Doubao/skills`。失效的旧默认配置会按此规则修复。
- 跟随 Junction 解析实际位置，在界面同时展示逻辑路径和重定向后的路径。

## 内置技能

### 手动配置来源目录

在「设置 → 工具技能 → 配置来源目录」填写所属工具、来源名称和绝对目录，点击「保存并扫描」。所属工具支持选择已有工具或输入未识别的产品名；同一工具可添加多个来源，并支持编辑和移除配置。配置保存在应用的 `config.json`，旧版本配置无需迁移。

选择直接包含 `<技能名>/SKILL.md` 的父目录，而非程序 EXE、整个安装目录或单个 `SKILL.md`。例如 DeepSeek Harness 的 `D:/软件/dsh/resources/runtime/office-skills`，以及插件包里的 `skills` 目录。保存前验证路径和标准技能结构；扫描不会递归搜索整棵安装目录。同路径同时自动发现和手动配置时优先使用手动来源。

手动来源参与技能浏览与复制，不依赖工具自动安装检测，也不授予 Agent 配置权限或证明工具已加载这些技能。目录失效后保留配置并显示提示，便于修正。来源目录保持只读，移除配置不会删除原技能；再次扫描仍可能自动发现该目录。

「设置 → 内置技能」展示来源、来源路径、实际路径、技能数量，以及每个技能的名称、描述和自身路径。

默认来源为各产品的明确用户技能目录，以及 WorkBuddy / Codex 的 `skills/.system`、WPS 灵犀的 `official_skills`。插件缓存、市场、程序安装包与内部连接器不再自动递归扫描。来源只枚举直接子目录，要求 `SKILL.md` 中存在有效名称与描述，不把普通 Markdown 算成技能。

同一物理目录可供不同产品共同读取，但这不代表能按产品独立禁用；共享目录与兼容目录的实际加载规则由各 Agent 决定。手动来源仍可由用户明确指定，保持只读，不证明已安装或加载。详细目录核查见 [共享与 Agent 目录说明](SHARING-AND-AGENTS.md)。

应用无法保证识别任意未知产品、任意便携安装位置或尚未下载的技能。没有发现标准技能时会显示空状态，允许手动配置路径。

## 实现参考

系统安装名与程序名由同一份产品知识库派生；扩充产品规则时也会扩充注册表、开始菜单和常见安装目录的匹配范围。实际程序必须与对应产品名称匹配，不能用任意图标或卸载器充当安装证据。

本次参考了以下开源项目的发现策略与职责划分，代码按当前 Rust/Tauri 架构实现，没有引入或复制这些项目的 UI、资源或运行时依赖：

- [vercel-labs/skills / agents.ts](https://github.com/vercel-labs/skills/blob/main/src/agents.ts)：将产品存在性检测与技能安装路径分开，尊重环境变量。
- [SkillBuddy / platforms.ts](https://github.com/konnga/skill-buddy/blob/main/packages/core/src/platforms.ts)：按产品定义用户目录与检测位置。
- [SkillBuddy / 平台约定](https://github.com/konnga/skill-buddy/blob/main/docs/platform-conventions.md)：区分可写技能目录与只读系统、插件来源。
- [SkillBuddy / Doubao adapter](https://github.com/konnga/skill-buddy/blob/main/packages/core/src/adapters/doubao-adapter.ts)：将内部 `.skills` 作为独立来源；Windows 路径使用本项目的本机实测和目录约定。
